# Очередь работы PropMind

Работа ведётся в Issues. Первые две задачи созданы: [UI-пилот #1](https://github.com/AlexNovikov77/propmind-design/issues/1) и [PDF-просмотр #2](https://github.com/AlexNovikov77/propmind-design/issues/2). Остальные пункты остаются проектом очереди до уточнения зависимостей. Основной код и интеграции развиваются в приватном propmind.

UI-пилот #1 завершён через PR #3, CI и публикация Pages прошли. [Инженерная настройка #4](https://github.com/AlexNovikov77/propmind-design/issues/4) вводит защищённый main, npm lock и Dependabot. Текущие статусы — в Issues; правила работы — в DEVELOPMENT.md.

## PM-001 — Рабочее пространство и Evidence Register

Приоритет: первый. Состояние: завершено через PR #3; проверки PR/main и публикация прошли.

Результат: навигация, сохранённые концепты, реестр PDF/IFC, доказательства, ручная приёмка, история, import/export, документация и CI.

Приёмка:
- Четыре страницы доступны с префиксом /propmind-design/.
- Замечания переживают перезагрузку браузера.
- Неполное доказательство нельзя подтвердить.
- Изменение проверенной записи требует новой приёмки.
- Невалидный импорт, конфликт вкладок и ошибка квоты не затирают текущий реестр.
- Подтверждены main, результат CI и опубликованная версия Pages.

## PM-002 — PDF: просмотр документа и выбор фрагмента

Приоритет: следующий. Состояние: [Issue #2](https://github.com/AlexNovikov77/propmind-design/issues/2).

Результат: загрузить локальный PDF в браузер, выбрать страницу и область мышью/касанием; координаты и снимок фрагмента перенести в замечание.

Приёмка:
- Выделение соответствует реальному исходному листу при масштабе и повороте.
- Фиксируются ревизия и хеш исходного файла.
- Оригинал не отправляется на сервер без выбранного пользователем сценария.
- Для изображений предусмотрены хранилище и экспорт; localStorage не используется для больших бинарных файлов.
- Обязательное подтверждение человека сохраняется.

Зависимость: выбрать средство PDF-просмотра и проверить его лицензию до добавления библиотеки.

## PM-003 — IFC: нормализованный элемент и связь с DTA

Приоритет: после PM-002. Состояние: готово к постановке.

Результат: получить элемент по GlobalId, его свойства, координаты и связь с оборудованием/помещением в общей модели.

Приёмка:
- Проверены единицы модели, цепочки размещения, система координат и ревизия.
- Повторный импорт различает прежний элемент и изменённую версию.
- Замечание содержит проверяемый исходный атрибут или фрагмент геометрии.
- На тестовой модели проверена цепочка помещение → BIM-элемент → оборудование → гарантия → заявка.
- Неподдерживаемые проверки явно помечены; коллизии не объявляются найденными без работающего расчёта.

## PM-004 — Общий реестр команды

Приоритет: до реальной совместной работы. Состояние: требует выбора инфраструктуры.

Результат: серверное хранилище, вход в аккаунт, роли, ревизии записей и надёжное хранение доказательств.

Приёмка:
- Нет перезаписи чужих изменений: контроль версий на сервере.
- Автор решения связан с учётной записью; журнал защищён от обычного редактирования.
- Восстановление из бэкапа проверено.
- Настроено разделение данных объектов и прав доступа.
- Согласованы место хранения и бюджет; после этого выбирается стек.

## PM-005 — Битрикс24: сначала чтение

Приоритет: после фиксации контракта данных и доступа к API. Состояние: готово к уточнению на реальном контуре.

Результат: связать замечание с реальной задачей/заявкой и показать актуальный статус без ручного дублирования.

Приёмка:
- Проверены права API и сопоставление ролей с действующей схемой заявок.
- Синхронизация идемпотентна; ошибки и время последнего обновления видимы.
- Секреты хранятся на сервере; в статических файлах и GitHub их нет.
- Создание задач, смена ответственных и статусов вводятся отдельной задачей после проверки чтения.
