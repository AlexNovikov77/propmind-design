# Разработка UI-пилота

Владелец продукта и кода: @AlexNovikov77. Основной код и рабочие интеграции — в приватном propmind; здесь только публичные интерфейсы, синтетические примеры и правила реестра.

## Рабочий цикл

Issue с пользователем, результатом и приёмкой → ветка → небольшой PR → validate и browser на текущем SHA → squash merge → CI main и проверка Pages. В работе не более двух продуктовых задач между обоими репозиториями.

Метки: priority: P0 — инцидент, P1 — ближайший результат, P2 — позже; status: ready/in-progress/blocked; area: ui. Актуальный статус review — открытый связанный PR, done — слитый PR с выполненной приёмкой. Следующая продуктовая задача: [локальный PDF-просмотр #2](https://github.com/AlexNovikov77/propmind-design/issues/2).

Активный ruleset PropMind main quality gate защищает основную ветку: PR, актуальная база, обязательные validate/browser от GitHub Actions, линейная история, запрет удаления и force-push. Исключения для обхода не выдаются. Пока сопровождающий один, approvals=0; при появлении второго включить 1 независимое одобрение. AI-ревью не выдаётся за независимое ревью человека.

CODEOWNERS определяет владельца, но не предоставляет права доступа. Dev-зависимости фиксируются package-lock.json; установка — npm ci --ignore-scripts. Dependabot раз в неделю предлагает npm/Actions обновления отдельными PR. Major-обновления рассматриваются отдельно; автоматического слияния нет. npm audit с порогом high включён в браузерный CI; это поиск известных advisory, не полный аудит приложения.

## Готовность и данные

- Пройден согласованный пользовательский сценарий, в том числе на телефоне; нет ошибок браузера.
- npm test, npm run check и browser проходят на точном SHA.
- Доказательство, источник, ревизия, координаты, ручная приёмка и история сохраняются при переносе.
- Изменение JSON имеет версию и план миграции; импорт повреждённого/старого формата не затирает данные.
- UI не обещает автоматический анализ PDF/IFC или интеграцию, которых ещё нет. Самостоятельный пилот AI требует отдельных измерений на реальном candidate и профильной приёмки.
- Клиентские документы, рабочие реестры, персональные данные и секреты не входят в коммиты и CI artifacts.

## Выпуски и откат

Версии — ui-vMAJOR.MINOR.PATCH на проверенном main. Release notes содержат результат для пользователя, Issues/PR, SHA, совместимость JSON и ограничения. .github/release.yml группирует заметки. Тег не означает доступность серверного хранения или production-интеграций.

GitHub Pages обновляется после merge main. При сбое — revert squash-коммита через PR с проверками, затем проверить восстановленную публикацию. Данные localStorage находятся у пользователя; возврат кода не откатывает их автоматически. Перед изменением формата нужен экспорт/миграция, совместимая с откатом.
