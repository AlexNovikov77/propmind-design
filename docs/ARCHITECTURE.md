# Архитектура v0.1

## Граница текущей версии

Статический сайт без сборки и серверного API. Браузер создаёт реестр вручную; никаких выводов от имени AI не генерируется. PDF Scan и IFC Deep Check представлены как два источника общей модели замечания.

| Слой | Файлы | Ответственность |
|---|---|---|
| Навигация | index.html | Рабочие разделы, статус функций |
| Интерфейс реестра | evidence/index.html, assets/evidence.mjs | Формы, карточки, фильтры, import/export, localStorage |
| Правила | assets/registry.mjs | Валидация, переходы статусов, повторная проверка, безопасный импорт |
| Представление | assets/site.css | Адаптивные страницы и диалоги |
| Концепты | concepts/liquid-glass/, b24/ | Исторические макеты на вымышленных данных |

## Общий контракт замечания

JSON верхнего уровня содержит schemaVersion: 1, updatedAt (ISO timestamp с часовым поясом) и массив findings. Идентификатор записи — устойчивый ER-UUID, при импорте он сохраняется.

| Поле | Назначение |
|---|---|
| id, title, project | Идентификатор, формулировка, объект |
| pipeline | PDF Scan или IFC Deep Check |
| severity | critical, high, medium, low — продуктовая критичность, без автоматической нормативной оценки |
| owner | Ответственный за разбор/устранение |
| sourceFile, revision | Имя исходного файла и его конкретная версия |
| excerpt | Точный текст или описание исходного фрагмента; до 4000 символов |
| location | Привязка к PDF или IFC, описанная ниже |
| status | draft, confirmed, resolved или dismissed |
| review | Кто, когда и с каким комментарием подтвердил запись |
| disposition | Кто, когда и почему отметил устранение или отклонение |
| createdAt, updatedAt, history | Временные метки и последовательность изменений |

PDF location: page (целое от 1), x, y, width, height в процентах от размеров видимой страницы. Начало координат — левый верхний угол. Прямоугольник должен лежать внутри страницы; для подтверждения его размеры строго больше нуля.

IFC location: globalId, x, y, z в метрах в системе координат исходной модели. Нули и отрицательные значения допустимы. В v0.1 нет чтения IfcUnitAssignment, трансформаций или геопривязки: человек приводит координаты к выбранной системе. Структура создаёт место для коннектора, но не имитирует его наличие.

Пустые координаты в черновике — null. Значение 0 не считается отсутствующим.

## Переходы и доказательство

- Черновик → подтверждено: нужны источник, ревизия, фрагмент, ответственный, полная корректная привязка и имя проверяющего.
- Подтверждено → устранено: нужны имя и комментарий о результате проверки.
- Черновик/подтверждено → отклонено: нужны имя и объяснение.
- Подтверждено/устранено/отклонено → черновик: имя и объяснение возврата.
- Изменение любого содержательного поля проверенной записи автоматически возвращает её в черновик и сбрасывает текущее подтверждение. Предыдущее решение остаётся в history.
- Сохранение без изменения содержимого сохраняет подтверждение.

Физическое удаление в пилоте отсутствует. Дубликаты и ошибочные записи отклоняются с объяснением.

## Надёжность данных

Импорт полностью валидирует файл до записи: версию схемы, размер, количество записей, идентификаторы, координаты, даты, допустимые статусы, обязательное подтверждение и события истории. Неизвестные поля отбрасываются. Значения пользователя выводятся только как текст DOM; HTML из JSON не исполняется. Реестр не делает сетевых запросов; CSP страницы запрещает подключение к API.

Замена реестра требует отдельного подтверждения пользователя в интерфейсе. Копия прежнего состояния записывается до замены. Если бэкап или новая запись не помещаются в localStorage, текущий реестр остаётся прежним. Копия содержит полный реестр, включая историю.

Перед записью интерфейс сравнивает снимок localStorage с загруженной версией. Обнаруженный конфликт с другой вкладкой отменяет сохранение и предлагает обновить страницу. Это защита от обычного последовательного конфликта, не транзакционная многопользовательская блокировка: для совместной работы нужен сервер и контроль версий на нём.

Хранилище использует ключи propmind.evidence.v1 и propmind.evidence.backup.v1. Все экземпляры на одном origin используют те же ключи. Импорт не проверяет личность авторов и подлинность history. Источники и криптографические хеши документов пока не хранятся.

## Следующий слой

Порядок развития: PDF с выделением фрагмента → IFC-коннектор и нормализованная модель → серверный реестр с авторизацией → чтение заявок Битрикс24. Каждый коннектор должен выдавать тот же контракт замечания и сохранять ревизию источника. Изменение формата требует новой schemaVersion и явной миграции.

Серверное хранилище, вход в аккаунт и независимая проверка доказательств обязательны до использования пилота как общего рабочего журнала команды. В эту ветку они не включены.
